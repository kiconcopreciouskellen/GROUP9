STACK, QUEUES AND BRACKET CHECKER
Name: WINYI ALVIN MUGISHA 

WHAT I BUILT
I built the array-based data structures and their screens a stack, a linear queue, a circular queue and a
bracket checker.

MY CLASSES 
Stack and Bracket Checker
CustomStack (LIFO):
Fixed-size array with push, pop, peek, size, isEmpty, isFull, and display.
Explicit boundary alerts for Stack Overflow and Stack Underflow.

BracketChecker:
This uses CustomStack to validate nested expressions like { ( [ ] ) }.
Logs stack snapshots at every symbol and stops immediately at the first mismatch.

Linear and Circular Queues
ArrayQueue:
This is a shared blueprint for queue operations.
LinearQueue (FIFO):
Pointers only move forward; dequeued slots are never reused.
Demonstrates the False Full Problem when rear hits the end despite empty front slots.

CircularQueue:
Wraps pointers around using (index + 1) % capacity.
Reuses freed slots so the queue is only full when every slot is occupied.

MY SCREENS
- StackPanel: one button for each operation. The stack is drawn as a column of slots with a TOP marker.
  A message appears after each operation.
- QueuePanel: one screen design that I use twice, for the linear queue and for the circular queue. It shows the
  array slots with FRONT and REAR markers and the front and rear indices. The linear version has a
  Demo: false full button. The circular version shows the rear wrapping around to index 0.
- BracketPanel: I type an expression, press Check, and read the stack after each symbol.

HOW I COUNT OPERATIONS
This module does not count operations. It shows a message and redraws the structure after every action.

HOW FAST THEY ARE
Every stack and queue operation takes constant time. The bracket checker takes time in proportion to the length
of the expression.
