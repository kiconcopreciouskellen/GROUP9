WHAT I WORKED ON:
Three recursive algorithms and two data structures

RECURSION
1. Factorial (Factorial.java)
   n! = n x (n-1)!, with 1! = 1. Inputs above 20 are rejected because the answer no longer fits in a long.
2. Fibonacci (Fibonacci.java)
   Two versions.
   - Naive: fib(n) = fib(n-1) + fib(n-2). It repeats the same work many times, so it gets very slow.
   - Memoized: saves each answer in a table the first time it is calculated, so each value is calculated once.
3. Tower of Hanoi (TowerOfHanoi.java)
   Moves n disks from peg A to peg C using peg B. Every move is logged.

DATA STRUCTURES
1. CustomStack (CustomStack.java)
   Last in, first out. push adds on top, pop removes from the top. Built on an array that doubles in
   size when full. Popping an empty stack gives an error, not a fake value.
2. CustomQueue (CustomQueue.java)
   First in, first out. enqueue adds at the back, dequeue removes from the front. Built on a circular
   array that doubles in size when full.

WHAT COUNTS AS ONE OPERATION
- Recursion: one recursive call. In Tower of Hanoi this equals the number of moves.
- Stack and queue: one push, pop, enqueue or dequeue.

SPEED (n = input size)
Factorial              n steps
Fibonacci naive        2 to the power n steps (very slow)
Fibonacci memoized     n steps
Tower of Hanoi         2 to the power n, minus 1 moves
Stack and queue        each operation takes constant time

TEST STEPS:
Factorial 5 gives 120 in 5 calls. Factorial 25 shows an error message.
Fibonacci naive 6 gives 8 in 25 calls. Memoized 30 needs only 59 calls, naive 30 needs 2,692,537.
Tower of Hanoi with 3 disks: 7 moves.
Stack with 10, 20, 30 and extra value 40: 40 is removed first.
Queue with 10, 20, 30 and extra value 40: 10 is removed first.
